# ADR-0004: 节拍提示投递通道升级——轮边界消息

日期:2026-10-06
状态:已验证(第二场纯态 28/28 全链路工作;增益归因待 tail 对照场)
前置:ADR-0002(事实化提示;第一场助推模式遵从率 59%)

## 背景

run-51061751 实测:事实化提示在 tool_result 尾巴位置的遵从率为 59%(13/22),
且三段爬升(25%→55%→86%)。流中送达的三次提示全部无视,落在解题边界的一次
(442)1 轮内遵从——注意力位置是残余 41% 未遵从的主要嫌疑。弱信号方案
(工具耗时=注意力空闲)被数据否决(被遵从/被无视提示的搭载工具耗时 0.1~3s 混布)。

## 决策

**status/review 节拍提示的投递通道从 tool_result 尾巴改为轮边界独立消息**:

- 通道:`pi.sendMessage({customType:"drift-guard-hint", content, display:true}, {triggerTurn:true})`;
- 实测形态(2026-10-06 探针验证):以 user 角色落在请求消息列表末尾——与用户
  steer 同一座位,模型必读;会话中以 custom 条目持久化(customType 保留);
- 范围:**仅 status/review**。转向提示与建档提示维持尾巴通道(单变量纪律,
  被测对象只是节拍);
- 对照开关:`PI_DRIFT_HINT_CHANNEL=tail` 回退旧通道,供同场 A/B;
- 工具结果不再被改写(旧通道的整体替换语义风险随之消失)。

## 已知权衡(通道纯度)

提示占用通常属于用户消息的高注意力通道。形态不变(事实链、零祈使、
`[导航状态]` 标记与来源标注自证身份,不冒充用户)——买注意力,让出位置的谦逊。
这是本 ADR 唯一的哲学让步,由用户裁决通过。

## 被否决的替代

| 方案 | 否决原因 |
|---|---|
| 语义时机检测(猜任务边界) | pi 事件词汇表是纯语法层;"猜自然语言"是文档第一章否决的同构问题 |
| 工具耗时代理信号 | 数据否决(无可分离阈值) |
| 提示进系统提示词 | 每轮可变内容核销前缀缓存,违缓存红线 |

## 后果与验证

- 单测 41/41(drift-guard 29 + system-inject 12):T7/T8/T20-T23 改验消息通道,
  新增 T29 旧通道对照;
- trace-report 同时识别两种通道(custom 条目 + 工具结果尾巴),旧会话回归
  59% 不变;
- 测试场:下一场纯态靶场(零 steer),遵从率对 59% 基线比较——同时回答
  助推水分与通道增益两个问题。
