# ADR-0005: 引导加固——通道、位置、空文档节拍

日期:2026-10-08
状态:已接受(待下一场靶场验证)
前置:ADR-0004(消息通道);RESULTS.md 四场引导记录

## 背景

导航系统全部机制以文件存在为前提,而建档是模型百分百的自由裁量——
引导是单点。四场实测的失败链:

| 场 | 引导结果 |
|---|---|
| 第二场 | 提醒后 1 轮建档,位置正确(幸运硬币) |
| 第一场 | 提醒无视 189 轮,里程碑自发改档 |
| on-1008 | 提醒无视 854+ 轮;锚引导形态(系统提示词)持续在场也未促成 |
| on-1008b | 1 轮遵从但**建进 tsec/ 子目录**→系统失联,文件随后弃养 |

座位证据:消息通道 28/28(status/review);尾巴通道的建档提醒 3 场 1 中。
1008b 另证:"PROGRESS.md"五字有位置歧义,歧义的代价是一整场。

## 决策

1. **建档提醒进消息通道**(与 status/review 同座,user 位末条)。
2. **位置写死**:提醒带绝对路径("工作目录根(<cwd>)没有 PROGRESS.md——本系统
   只从运行目录读取");锚引导骨架与 checkpoint 工具描述同步写明
   ("运行目录根,勿放进子目录")。
3. **空文档回顾事实**:无文件时 review 节拍不再整体短路,降级为一条事实句
   ("已 X 轮,导航文件仍未建立…")——每 100 轮最多一条,建档即止。
   非重发旧提醒(红线禁的是逐轮轰炸/重发),是回顾节点上的新事实,
   单测 T30 固化"非复读"断言。

转向提醒维持尾巴通道(事件驱动,跟随原始 steer 事件)。

## 被否决/搁置的替代

| 方案 | 处置 |
|---|---|
| 系统自己创建 PROGRESS.md | 否决——系统开始替模型在世界里动手,越过"只播报不行动"的界;文件所有权与信任语义全变 |
| 无文件期间每 150 轮重申建档 | **搁置为阶段二**,需红线裁决;先看阶段一实测,空文档回顾事实(100 轮节奏)已部分覆盖此需求 |

## 验收(下一场靶场预注册)

前 50 轮内、正确位置(工作目录根)建档;建档后节拍接管,维护 ≤60 轮/次;
全场复刻第二场轨迹(≥8 分/轮、跑满时限)。

## 修订记录

**2026-10-08 三轴代码审查(Standards/Spec/最高原则)后的修正**:

1. **零祈使两处越界修复**:引导骨架与工具描述中的"勿放进子目录"改为事实句
   "本系统只从运行目录读取"——"勿"是祈使标记,且原句逃逸了 T20 检测
   (T20 只扫消息通道文案;现已把空文档事实文案纳入红线族,T20 覆盖 5 段)。
2. **trace-report 分类契约修复**(审查抓到的最重要 bug):新建档文案删掉了
   "无导航文件"特征词、空文档事实复用 [回顾状态] 前缀,导致两者分别被误判为
   status/review 混入遵从率、建档计数恒零——下场验收数据会被污染。
   修复:hintKind 增设 empty 类("仍未建立"先判)、doc 兼容新旧文案,
   空文档事实与建档提示均不计入遵从率;1008b/第二场回归验证分类正确。
3. 同文件三处重复的通道分派四行式提取为 deliver() 助手(Fowler:Duplicated Code);
   陈旧注释(仍写"建档保持尾巴通道")与优先级注释(未含空文档节点)更新;
   docHint/emptyReviewHint 尾句措辞统一;建档分支补 lastNudgedTurn
   (防稀疏工具会话中与空文档事实同轮背靠背连发)。
4. T9 补绝对路径断言(process.cwd() 实际出现);T30 补"建档即止"与
   窗口中段静默负例。
5. **遗留待裁决(灰区)**:空文档事实在模型持续不建时会每 100 轮重问
   "是否建立"——重审模型已隐式回答的决定,越久越近 nagging;且 ADR 搁置了
   更疏的 150 轮重申却落地了更密的此机制。裁决选项:上限三条/间隔翻倍/
   后续条目只报事实不附问句。另:锚引导形态中"建议先建立它"为 ADR-0002
   红线(零祈使族)之前的历史文案,是否追溯由用户定。

## 二轮审查修订(2026-10-08,三轴严苛复审)

上轮四项修复经 12 例分类复演与边界走查全部核实;新增修正:

1. **空文档事实删去问句尾巴**("是否建立由你判断"整句移除,只留纯事实)——
   两轮一致裁定灰区偏越界,判准:status 尾句重开的是"陈旧事实"(模型从未
   就变陈旧表态)故为白;空文档尾句重开的是"要不要建档"(建档提醒已问过
   一次且模型以百轮不建作答)故为重问。判断权授予由建档提醒一次性完成即止。
2. **T30 末断言收紧**:350 轮两钟皆到期,review 必然先出——原"二者之一"
   使 status 优先级分支永不可达(回归不会被抓);现钉死 [回顾状态]+未深度回顾。
3. **T9 补分类器锚词断言**("没有 PROGRESS.md"):trace-report 零单测,
   文案改动曾致分类静默退化(上轮 bug 的复发路径)——生产侧锚词由测试钉住,
   改文案必须两处同步的契约现被强制。
4. 边界走查确认:中途删文件后建档提醒不会重发(docReminded 运行内不复位,
   "仅一次"语义成立);EISDIR 正确走读取失败降级;steer 直连 appendHint
   系规格行为;两通道 turn 归属与遵从窗口口径一致。
5. **待用户裁决清单**(不单方面改,涉及锚文案的历史延续与实验可比性):
   - 锚骨架遗留祈使:"建议先建立它"→"链路较长时通常值得建立";
     "照抄骨架填空"→"建立时可用此骨架";工具参数"无需调整请明说"→"无调整则填'无'";
   - 判别实验(通道贡献归因):同事实文案做"带/不带判断权尾句"或"中性前缀"A/B,
     遵从率不降才证明是事实在说服而非 user 末位座位在强制(28/28 区分不了二者);
   - "仍未建立"在"建过又删"场景措辞不严谨(低危,改则须同步分类锚词)。
