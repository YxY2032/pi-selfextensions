# ADR-0002: 事实化提示家族与节拍重调

日期:2026-10-06
状态:已接受(效果待测试场裁决)
前置:ADR-0001(单一导航系统)
工单:.scratch/fact-hints/

## 背景

真实靶场会话(964 轮)的实测:drift-guard 机制全部按设计运作(节拍准时、提示送达、
追加不替换),但模型对"建议调用 checkpoint"式提示的遵从率极低——964 轮仅 3 次
checkpoint + 4 次直接写导航文件,提示后模型的下一段文本 4 个采样全部直接继续攻击流。
根因:提示是工具结果末尾的一行祈使式建议,在高强度任务流中注意力权重趋近于零;
且"提示即消费时钟"决定了系统永远轻声说一遍、永不升级。

## 决策

1. **提示全家族事实化**。四条提示(status / review / 建档 / 转向)统一为三要素结构:
   **数字事实**(已 X 轮未更新)+ **对照物引用**(上条 Now / 整体 Goal / 最近回顾自省,
   各截断 80/60 字符、注明来自 PROGRESS.md、读文件失败降级为纯数字事实)+
   **疑问句或判断权声明**(是否仍一致 / 判断在你)。全家族**零祈使句**——哲学红线
   固化为单测 T20(断言全部提示文案不含 建议/请/必须/应该/务必)。
2. **节拍重调**:status 10→50 轮、review 20→100 轮(1:2 比例不变)。
   依据:模型自然维护节奏 ≈ 140 轮/次(7 次更新 ÷ 964 轮);提示量 132 → ~14,降噪 90%;
   降频本身提高单条被读概率。建档阈值 15 次调用不变(一次性、防压缩、无噪声问题)。
3. **双时钟分离**。节拍时钟(lastStatusTurn/lastReviewTurn,提示即消费,防逐轮轰炸)
   与陈旧事实基准(lastNavWriteTurn/lastActualReviewTurn,仅真实导航更新才推进)分离。
   "已 X 轮未更新"的 X 反映文件内容新旧而非提示历史——提示绝不重置事实;
   模型直接 write/edit 导航文件同样推进事实基准(虚假的陈旧数字比没有更糟)。
4. **判据先于实现锁定**(执行→测试→判断):
   - 遵从率 = 提示(status/review)送达后 25 轮内发生导航更新(checkpoint 或直接写
     PROGRESS.md)的比例;`trace-report.mjs --compliance` 自动出数;
   - ≥40% 且任务表现不掉 → 有效;10%~40% → 调参再测(最多两轮,不上第三种机制);
     <10% → 措辞回滚,节拍数字保留,结论"中性事实不足以撬动任务惯性"入档;
   - 只认真实会话;两场同向才下最终结论。

## 已知限制(如实入档)

- **同船混杂**:措辞与间隔同时生效,结果落在中间带时无法区分各自贡献;
  调参轮可做单变量分离。
- **基线口径**:旧会话逐字复算为 17%(23/132)——密集节拍下 25 轮窗口覆盖约 3 条
  提示,单次更新被多条满足;新节拍(50 轮间隔 > 25 轮窗口)下不可能重叠,指标自洽。
  判据采用绝对阈值,不受基线口径影响。
- 引用内容是仓库文件数据进**消息流**(工具结果),非系统提示词,信任门不受影响
  (模型本可自行 read 该文件);引用处注明来源,与锚的数据标注同一防御逻辑。

## 收益(顺带)

Goal 每 50 轮随提示重演,缓解 handoff 遗留的"压缩缝隙":上下文压缩后锚在新前缀
中消失,但事实化提示周期性带回 Goal,导航自愈,无需动压缩钩子。

## 被否决的替代

| 方案 | 否决原因 |
|---|---|
| 提示升级阶梯(忽略后换更强措辞) | 升级轨道=施压,违反最高原则;复杂度上升 |
| 只改措辞不动间隔 | 密集节拍的习惯化效应会污染措辞实验 |
| 把"已 X 轮未更新"写进锚 | 动态内容进系统提示词,违反缓存红线 |
| 逐轮重提直到调用 | 违反"不轰炸"红线(历史决策,维持) |
| 按时间(分钟)计节拍 | turn 是系统天然单位,节拍器本就挂在 turn_end |
